Compare the origination strategies

Four ways to originate a line, one harness, one clock, 148 verified games. Every forecast for week w was built only from weeks before w, so nothing is measured with hindsight. Controls sit in the same table because a strategy that cannot beat a coin flip or a pick'em is not a strategy.

The headline, before any number: four origination strategies were run walk-forward over 148 verified games. S2 (Offence meets defence) is ahead on spread error at 10.03 points MAE against 10.66 for a pick'em control. 10. Suggestions — paths to choose, not changes already made

This section exists so a suggestion can be reviewed and a path chosen before anything is implemented. Each entry carries its alternatives, a recommendation, its cost, its risk, and the evidence in the repo that supports it. Nothing here has been applied.

SC-01 — Show the winner as 'not yet established', with the number that would establish it

Problem. The lab can rank four strategies, but the intervals overlap and none survives the multiplicity adjustment. A leaderboard that shows a rank invites the reader to act on noise.

Paths. (a) Show no rank at all until the threshold is met. (b) Show the rank with the interval and the required-n column beside it. (c) Show the rank and a 'significant' badge.

Recommended. Path (b). It answers the user's question honestly - who is ahead, by how much, and how little that means - without hiding the ordering or implying it is real.

Cost. One already-built table.  ·  Risk. A reader still screenshots the top row out of context; mitigate with the required-n column in the same row, not a footnote.

Unblocks. QO-02, QO-13, R060  ·  Evidence in repo. data/compare/evaluation.csv

SC-02 — Make dispersion a first-class published column, not a diagnostic

Problem. Under-dispersion (0.26-0.58) is the mechanical reason no line is bettable, and it is invisible on the current site.

Paths. (a) Leave it in the lab only. (b) Publish it beside every originated line, with a one-line reading guide. (c) Add a hard gate that blocks publishing a line whose dispersion is below a set threshold.

Recommended. Path (b) now, path (c) only after the shrinkage is re-fitted - a gate on a number we cannot yet improve would block the site rather than the model.

Cost. Low: one column and one sentence.  ·  Risk. A threshold set from 132 games would be arbitrary; do not pretend it is a league standard.

Unblocks. QO-04, R051  ·  Evidence in repo. data/compare/evaluation.csv

SC-03 — Retire the totals leg to 'league mean plus nothing' until signal exists

Problem. Predicted total versus actual total correlates at -0.03, and a control that ignores the teams beats every strategy on total MAE.

Paths. (a) Keep publishing a model total. (b) Publish 'league mean' as the total with the model's deviation shown separately as an unvalidated opinion. (c) Stop publishing totals.

Recommended. Path (b). It keeps the two-estimator comparison alive (R051), states plainly that the total is the control, and stops a weak number being presented as a model output.

Cost. Trivial: relabel two columns.  ·  Risk. Readers may read 'league mean' as a prediction; label it as the control that won.

Unblocks. QO-03, R051  ·  Evidence in repo. data/compare/evaluation.csv

SC-04 — Fix the scheduled availability capture before adding any availability feature

Problem. The one workflow that would create a legal point-in-time record has never had a successful run; its 2026-11-17 run failed. Without it every availability feature is untestable.

Paths. (a) Build more availability features now. (b) Repair the capture workflow first and prove one clean week. (c) Drop availability from the model.

Recommended. Path (b). It is the cheapest item on this page and it unblocks four other requirements at once.

Cost. One workflow repair and one week of waiting.  ·  Risk. The official page may change structure mid-week; the workflow's drift check already fails loudly rather than storing garbage - keep that behaviour.

SC-05 — Publish the Week 11 slate now, with the market columns blank

Problem. The forecast is only prospective if it exists before kickoff. Week 11 has no injury report yet, so a forecast made today is a legal (if uninformed) pre-kickoff registration.

Paths. (a) Wait for the injury report. (b) Publish now with the report-dependent features explicitly absent, and re-issue a second registration when the report lands. (c) Publish one forecast after the report and call it pre-kickoff.

Recommended. Path (b). Two dated registrations are stronger evidence than one, and the diff between them is the injury signal - which is exactly the surprise the brief asks for.

SC-06 — Make the multiplicity count a committed number, not a post-hoc one

Problem. Every extra strategy searched increases the chance that the best one is luck. The lab declares 12 comparisons today; a future session could add arms and quietly change the threshold.

Recommended. Path (b). It is a five-line guard and it is the difference between a pre-registration and a story.

SC-10 — Add an injury/personnel ablation harness rather than penalty weights

Problem. The brief asks for ablations, not fixed penalties. The repo's model still ships position penalty weights that were never validated (QB 2.6 points, WR 0.55, and so on).

Paths. (a) Tune the weights on 148 games. (b) Run the same model with and without a personnel block and report the paired difference with an interval. (c) Drop personnel entirely.

Recommended. Path (b). It is the only version that can answer 'does this feature help' without fitting the answer into the weights; and on 148 games it will very probably report 'no measurable difference', which is a useful result rather than a failure.
