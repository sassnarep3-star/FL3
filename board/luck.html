Removal of luck — the first prospective grade

This page answers one question, for the first time with evidence rather than assertion:

Did the numbers on this site beat a coin flip, or did they get lucky?

Short answer: a bit of both, and the sample is far too small to say which. Read the rest of this page before quoting that sentence without it.

Method, and why each choice was made

  • The forecast was frozen before kickoff. data/lines_week10.json carries

meta.model_run_date = 2026-11-14. It was written before the Sunday 2026-11-15 slate.

  • The Thursday game is excluded. WAS-NYG (24-21) was already final when the forecast file was

written, so scoring it would be scoring a post-hoc number. It appears in the results table and not in the headline sample. Headline n = 11.

  • Every game counts once. The Brier interval is a game-level bootstrap (20,000 resamples,

seed 20261116), not a per-observation interval, because games are the unit that was forecast.

  • Two benchmarks, both reported. A coin flip is a weak benchmark; anyone can beat a coin.

The sample's own base rate is the honest one, and it is the one that hurts.

  • No p-value, no ROI, no CLV. n=11 cannot support a p-value; there is no licensed price to

compute ROI or closing-line value against (Q-01 / FLG-010). Both are listed as missing rather than estimated.

Two things follow, and they are the whole point of this page:

1. The coin-flip win is not established. The bootstrap interval on the skill score runs from slightly negative to strongly positive. On 11 games that is what "we cannot tell yet" looks like when you write it down honestly instead of rounding it to a win. 2. The right benchmark beats the model. Home teams won only 3 of 11 games in this sample. A model that never deviates from "27% home" would have scored slightly better. This is a property of a small, skewed sample more than a verdict on the model — which is exactly why the model cannot be declared good or bad from it.

Pricing error, decomposed

A single error number hides two different diseases. Bias is a constant offset and is cheap to fix. Dispersion is how spread out the model's opinions are compared with reality, and it is not cheap.

This is the most actionable finding in the repository. The model varies its forecast spread across games by about 3.4 points. Reality varied by about 14.4. A forecast that is nearly constant cannot pass a line test however good its average is, and the repository's own availability adjustments are applied at a scale far smaller than the noise they are meant to explain. Fixing bias does not fix this; the opinion distribution itself has to widen, and widening it requires knowing which games are genuinely more uncertain — which needs the inputs this repo does not yet capture.

The model won 1.4 more games than it predicted it would. Those 1.4 wins belong to variance, not to the model, and a leaderboard that ranked on win rate would have paid for them. This is the concrete reason the brief asks for signal and staking to be separated: at n=11 the gap between "What happened" and "What was expected" is larger than most models' entire edge.

The lowest-confidence bucket went 0 for 4. With four games that is noise, and it is reported as noise. But it is directionally the same skew as the +7.91-point bias: in this sample the model was too confident about home teams that lost.

What would change our mind

Per the rule that every strategy entry carries a two-sided reversal condition, so does this page:

  • Evidence the model has skill: a walk-forward sample of 200+ games, a Brier skill interval

against the base-rate benchmark whose lower bound clears zero after a multiplicity adjustment for the number of strategies tried, and a dispersion ratio that rises above ~0.7.

  • Evidence the model has none: the same test run on 200+ games where the base-rate benchmark

still wins. That outcome would retire the model rather than tune it.

Neither test can be run today: the repository has one scored week and 33 verified game rows.
