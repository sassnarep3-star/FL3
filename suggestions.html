SG-01 Write a source contract for every official page we use

implemented

Problem. Right now each dataset was captured by hand once. There is no written agreement about which page owns which field, or what happens when a page changes shape.

Unblocks: Q01

data/sources.json now records publisher, fields used, verification state and a rejection list. The refresh job (SG-02) enforces it.

Path A · Hand-curated registry recommended
effort: low · cost: free
+ Exact, reviewable, no scraping fragility beyond the four pages we already read.
− Breaks silently if NFL.com renames a column.
Path B · Scrape everything with selectors
effort: high · cost: free
+ More fields per page.
− Every selector is a liability; no SLA; likely violates nothing but is fragile.
Path C · Buy a data vendor
effort: low · cost: recurring fee
+ Stable schema.
− No longer an 'official source' claim; costs money.

Decision needed: Accept that four hand-verified pages are the foundation, or approve a vendor budget.

SG-02 Freeze the line at kickoff and never edit it

implemented

Problem. An originated line is worthless for grading if it can be quietly improved after the game.

Unblocks: Q02, Q08

Git history is the audit trail. .github/workflows/verify.yml re-derives every number from the committed data on each push and fails if the published pages drift from the committed JSON, so a line cannot be quietly improved after the fact.

Path A · Weekly commit at first kickoff recommended
effort: low · cost: free
+ Simple, auditable, works with the CI already in place.
− Depends on the job running on time.
Path B · Signed tag per week
effort: medium · cost: free
+ Cryptographic proof of when the line was fixed.
− Extra ceremony for a single-owner repo.
Path C · No freeze
effort: none · cost: free
+ Frictionless.
− Destroys the credibility of every future grade. Not a real option.

Decision needed: Choose the freeze mechanism. Until then, treat all grades as provisional.

SG-12 Choose the reward weighting explicitly

proposed

Problem. sqrt(n) normalisation rewards precision over volume, which is a values choice, not a fact.

Unblocks: Q12

Path A · Precision-weighted (current) recommended
effort: none · cost: free
+ Punishes volume-chasing; rewards selectivity, which is what you asked for.
− Rewards abstention; a strategy that bets twice a year and wins both looks great.
Path B · Total-profit-weighted
effort: none · cost: free
+ Intuitive.
− Rewards volume; a lucky high-volume strategy beats a skilled selective one.
Path C · Run both and publish a spread
effort: low · cost: free
+ Shows how much the ranking depends on the choice.
− Two leaderboards to explain.

Decision needed: Confirm precision-weighting, or switch to profit-weighting.

SG-20 Treat dispersion, not bias, as the top modelling priority

proposed

Problem. Across 11 pre-kickoff forecasts the model's margins have sd 3.41 while realised margins have sd 14.39 - a dispersion ratio of 0.24 (board/luck.html). Bias is +7.91 pts and accounts for only 28% of MSE. A near-constant forecast cannot beat a market however good its mean is.

Unblocks: R069, F24

Blocked by: Nothing - can start immediately

Path A · Re-centre only (remove the +7.91 bias)
effort: low · cost: free
+ Cheap; removes 28% of the squared error immediately.
− Does not touch the 72% that is dispersion. Would improve MAE and change nothing about the ability to find an edge.
Path B · Widen uncertainty with a game-specific variance model recommended
effort: medium · cost: free
+ Attacks the actual defect. Rest-day, travel, neutral-site, roof and divisional-vs-cross-conference are published schedule facts available today.
− More parameters on a sample of 11 games; risks fitting noise and needs strict pre-registration.
Path C · Keep a fixed sigma and stop quoting probabilities
effort: low · cost: free
+ Honest - if the model cannot express uncertainty, publishing only a point line with a wide band is defensible.
− Gives up the proper-score leaderboard, which needs a probability.

Decision needed: Is dispersion the accepted top modelling priority, and is the variance model pre-registered before the next window?

SG-21 Replace fixed availability point-penalties with a pre-registered paired ablation

proposed

Problem. The engine subtracts fixed points per missing player by position (QB 2.6, CB 0.5, ...). Those constants are assumptions, not measurements, and depth rank does not tell us how much worse the replacement is (board/depth-evidence.html).

Unblocks: R028, R029, F19

Blocked by: Needs a multi-week snapshot series (SG-19) and a results corpus

Path A · Fit the per-position penalty from settled games
effort: medium · cost: free
+ Still publishes one number per position, easy to explain.
− Requires enough games with a clean before/after; with one week it would fit noise and become a new unvalidated constant.
Path B · Paired ablation: identical model with and without availability features, chronological folds, interval on the difference recommended
effort: medium · cost: free
+ Answers the real question - does the availability signal add anything? - and reports uncertainty instead of a point estimate.
− Cannot run until there is a multi-week snapshot series (SG-19) and a results corpus.
Path C · Drop availability from the model until it can be validated
effort: low · cost: free
+ Most honest for immediate publication; removes four unvalidated constants.
− Discards the one input the brief cares most about, and the availability signal is visibly real even if its size is unmeasured.

Decision needed: Target a paired ablation, or drop availability from the model until it can be validated?
