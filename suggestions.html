SG-01 Write a source contract for every official page we use

implemented

Problem. Right now each dataset was captured by hand once. There is no written agreement about which page owns which field, or what happens when a page changes shape.

Unblocks: Q01

data/sources.json now records publisher, fields used, verification state and a rejection list. The refresh job (SG-02) enforces it.

Path A · Hand-curated registry recommended
effort: low · cost: free
+ Exact, reviewable, no scraping fragility beyond the four pages we already read.
− Breaks silently if NFL.com renames a column.
Path B · Scrape everything with selectors
effort: high · cost: free
+ More fields per page.
− Every selector is a liability; no SLA; likely violates nothing but is fragile.
Path C · Buy a data vendor
effort: low · cost: recurring fee
+ Stable schema.
− No longer an 'official source' claim; costs money.

Decision needed: Accept that four hand-verified pages are the foundation, or approve a vendor budget.

SG-02 Freeze the line at kickoff and never edit it

implemented

Problem. An originated line is worthless for grading if it can be quietly improved after the game.

Unblocks: Q02, Q08

Git history is the audit trail. .github/workflows/verify.yml re-derives every number from the committed data on each push and fails if the published pages drift from the committed JSON, so a line cannot be quietly improved after the fact.

Path A · Weekly commit at first kickoff recommended
effort: low · cost: free
+ Simple, auditable, works with the CI already in place.
− Depends on the job running on time.
Path B · Signed tag per week
effort: medium · cost: free
+ Cryptographic proof of when the line was fixed.
− Extra ceremony for a single-owner repo.
Path C · No freeze
effort: none · cost: free
+ Frictionless.
− Destroys the credibility of every future grade. Not a real option.

Decision needed: Choose the freeze mechanism. Until then, treat all grades as provisional.

SG-05 Use snap counts as the depth-chart substitute

blocked

Blocked by: no official snap-count feed captured

SG-12 Choose the reward weighting explicitly

proposed

Problem. sqrt(n) normalisation rewards precision over volume, which is a values choice, not a fact.

Unblocks: Q12

Path A · Precision-weighted (current) recommended
effort: none · cost: free
+ Punishes volume-chasing; rewards selectivity, which is what you asked for.
− Rewards abstention; a strategy that bets twice a year and wins both looks great.
Path B · Total-profit-weighted
effort: none · cost: free
+ Intuitive.
− Rewards volume; a lucky high-volume strategy beats a skilled selective one.
Path C · Run both and publish a spread
effort: low · cost: free
+ Shows how much the ranking depends on the choice.
− Two leaderboards to explain.

Decision needed: Confirm precision-weighting, or switch to profit-weighting.

SG-17 Test whether club-published depth charts are usable at all

proposed

Problem. The league does not publish a machine-checkable depth ordinal, but individual clubs sometimes publish dated depth charts. Whether those are consistent, timely, or stable enough to use has never been tested.

Unblocks: Q05, M04

Path A · Sample 4 clubs for 3 weeks and measure agreement recommended
effort: medium · cost: free
+ Produces a real number: how often do club charts agree with who actually started?
− Club sites are not nfl.com, so any value derived this way may not meet the official-source rule.
Path B · Skip club charts; use participation counts only
effort: none · cost: free
+ Keeps a single, official evidence standard.
− Leaves a possible source unexplored.

Decision needed: Say whether club-published charts count as evidence, even though they are not nfl.com.
